# nexrad-geojson

Create GeoJSON from NEXRAD Archive II Level 2 data.

Each radial gate becomes a polygon covering the wedge between its range and
azimuth bounds, projected with the WGS84 ellipsoidal orthographic projection
centered on the radar. One file is written per requested elevation.

This crate is a dependency-light Rust port of
[`jtleniger/go-nexrad-geojson`](https://github.com/jtleniger/go-nexrad-geojson)
(MIT) at commit `53e2aa5fd7a5ffba06ad4e3089f001b46b646a67`. It produces the same
GeoJSON layout without a Go toolchain or PROJ runtime dependency.

## Build

```sh
cargo build --release
```

## Usage

```text
nexrad-geojson [OPTIONS] <INPUT>

-l, --log-level <LEVEL>   [default: warn]   debug|info|warn|error
    --minimum <F32>        minimum product value to include
    --maximum <F32>        maximum product value to include
-p, --product <PRODUCT>   [default: REF]    REF|VEL|SW|ZDR|PHI|RHO
-e, --elevations <RANGE>  [default: 1]      N or N-M (inclusive)
-o, --output <BASE>       [default: radar]  base filename
```

For example, `--output data/nexrad-latest -p REF -e 1-3` writes
`data/nexrad-latest-REF-1.json`, `data/nexrad-latest-REF-2.json`, and
`data/nexrad-latest-REF-3.json`.

## Test

```sh
cargo test
```

The integration test compares output against
`tests/fixtures/ktlx-mini-REF-1.expected.json`, generated by the upstream Go
tool from the trimmed real KTLX volume in `tests/fixtures/ktlx-mini.ar2`.
